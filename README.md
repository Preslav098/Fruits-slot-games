# Fruit Slots — обновена версия

## Стартиране

Нужен е Node.js 22.12+ (проверено с Node.js 24).

```bash
npm ci
npm start
```

Отвори адреса, показан от Vite, обикновено http://localhost:5173.
`npm start` стартира API на 127.0.0.1:3001 и frontend. Ctrl+C спира двата процеса.

Поотделно в два терминала:

```bash
npm run dev:api
npm run dev
```

## Управление

- SPIN или Space: заявка за нов резултат.
- STOP или Space по време на въртенето: ускоряване до получения от сървъра резултат.
- +/-: залог от 10 до 100, със стъпка 10. Блокирани при spin.
- След refresh се възстановяват балансът и последният резултат чрез cookie сесия.

## Архитектура

- `backend/engine.mjs`: криптографски RNG чрез `crypto.randomInt`, стоп позиции, видими символи и печалби.
- `backend/config/reel-strips.json`: пет физически ленти. Повторенията определят вероятностите, а редът определя съседните групи символи.
- `shared/game-config.json`: линии, paytable, лимити за залога.
- `shared/contracts.ts`: формати на session, spin result и събитията.
- `backend/server.mjs`: session, spin API, Server-Sent Events и защита срещу повторно таксуване със същия requestId.
- `frontend/src/Game.ts`: init → beforeSpin → onSpinResponse → afterStop → cleanup/destroy.
- `frontend/src/api/SlotApi.ts`: HTTP заявки и SSE връзка.
- `frontend/src/reel/Reel.ts`: неподвижна рамка, маска и движещи се символи.
- `frontend/src/reel/ReelStrip.ts`: визуална лента; няма право да определя печалбата.
- `frontend/src/reel/ReelAnimator.ts`: движение и ускоряване при STOP.
- `frontend/src/config/SpingConfig.ts`: продължителност, разлика между риловете, обороти и blur.

Един spin връща `spinId`, `stops`, `grid`, `winningLines`, `totalWin`, `bet` и крайния `credits`. Backend изпраща и `spin:result` по SSE. HTTP отговорът управлява анимацията на заявилия клиент; SSE синхронизира idle клиенти.

Печалбите запазват формулата от оригиналния проект: `bet × multiplier × (count − 2)` за поне три еднакви символа отляво надясно. Всеки залог активира петте линии. Показват се последователно всички печеливши линии.

## Проверки

```bash
npm test
npm run build
```

7 автоматични теста: wrap на лентите, печеливши линии, прекъснат match, невалиден залог, недостатъчен баланс, съответствие на стопове/резултат/баланс, HTTP/SSE/idempotency/refresh/изолация на сесии.

Ръчна визуална проверка:

1. SPIN — символите трябва да се движат вертикално, рамките остават неподвижни.
2. STOP/Space — всички рилове спират бързо; показаните символи съответстват на `/api/session` → `lastSpin.grid`.
3. +/- са блокирани по време на заявката и анимацията.
4. Refresh запазва баланса и последния резултат.
5. Промени размера на прозореца — цялата сцена се мащабира и центрира.
6. Спри API и пробвай SPIN — показва се грешка; при възстановена връзка повторението използва същия requestId.

## Текущи ограничения

Това е демо с виртуални кредити. Сесиите са в паметта и се нулират при рестарт на API; неактивните изтичат след 24 часа. Следващата стъпка за устойчиво съхранение е база данни с транзакции. Идемпотентността пази последните 1000 заявки на сесия.

Лентите са начална конфигурация, а не калибриран RTP. Математическият модел и payout формулата трябва да се анализират преди баланс на играта.

Рамката е един Sprite, а лентата използва пет рециклирани Sprite обекта зад маска. Това реализира плавно движение без тресене; не е една предварително изпечена текстура за цялата лента.

Визуален browser тест не е изпълнен в средата за подготовка, защото липсва инсталиран Chromium. Build и backend тестовете са изпълнени успешно.

Оригиналните `src/`, `public/` и `backend/src/` са оставени за справка; активният frontend е `frontend/src/`, активният API е `backend/server.mjs`. Те не се използват за изчисления в браузъра. `vite preview` показва production build-а, но за API е нужен proxy към порт 3001; `npm start` включва този proxy за локална разработка.
